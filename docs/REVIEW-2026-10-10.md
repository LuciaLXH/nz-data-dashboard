# Refresh incident and project review — 2026-10-10

A scheduled refresh passed data validation and tests but failed when creating
a GitHub Pages deployment. Recovery exposed two additional resilience issues:
artifact collisions on reruns and an incompatible cache format after adding
validation history. All three issues were investigated and the hardened
pipeline was deployed successfully.

## Initial failure

[Run 37996530712](https://github.com/LuciaLXH/nz-data-dashboard/actions/runs/37996530712)
used commit `39b0b18`. It started at 2026-10-09 21:57:46 UTC
(2026-10-10 10:57:46 NZDT). Deployment failed at 11:05:16 NZDT.

| Stage | Result |
|---|---|
| Restore previous snapshots | Successful |
| Fetch population | Six regions, 48 region-year records |
| Fetch flow | HBRC: two successful sites, one failed; ORC: eight successful sites |
| Transform and validate | 14/14 checks passed |
| Tests | 24 passed |
| Upload Pages artifact | Successful, approximately 1.96 MB |
| Create Pages deployment | HTTP 502 |

`actions/deploy-pages@v4` failed at the deployment API request, with request ID
`4403:A4663:2C6DE4F:90A8C45:6AC96511`. This identifies a deployment-server
error; it does not establish a platform-wide GitHub outage. Runtime deprecation
warnings were separate from the observed failure.

The previous workflow had one job. Its final step failed, so the notification
reported that all jobs had failed even though data processing passed. The new
build was not published; the site continued serving its previous deployment.
Evidence: [original log](incidents/2026-10-10/failed-run.log).

## Recovery sequence

1. Saved the original logs and reviewed recent runs; the preceding nine were
   successful.
2. Reran failed jobs with `gh run rerun 37996530712 --failed`. Attempt 2 again
   passed validation and 24 tests, but deployment found two artifacts named
   `github-pages` within the same run. The old cache key also lacked an attempt
   identifier. Evidence: [attempt 2 log](incidents/2026-10-10/rerun-attempt-2.log).
3. Dispatched a new workflow run, avoiding the artifact collision.
   [Run 38009523209](https://github.com/LuciaLXH/nz-data-dashboard/actions/runs/38009523209)
   published successfully with all 11 sites. This recovered the original
   version; it did not yet verify the subsequent hardening changes.
4. Published the hardened workflow in commit `e422518`.
   [Run 38016497701](https://github.com/LuciaLXH/nz-data-dashboard/actions/runs/38016497701)
   passed 30 tests and 14 validation checks and deployed successfully. However,
   the old snapshot cache was not restored, leaving only 10 sites after one
   HBRC request failed. The page correctly reported degraded coverage.
5. Added a raw-only legacy-cache migration in commit `4207b06`.
   [Run 38017303548](https://github.com/LuciaLXH/nz-data-dashboard/actions/runs/38017303548)
   restored the legacy snapshot, retained failed sites, and published all 11.

The cache issue arose because GitHub's cache version includes the configured
path list. Adding `_runs.jsonl` changed that version, so a matching key prefix
alone could not restore older raw-only caches. The migration step uses the
original two paths when the new cache has no match. Successful builds then save
the full cache under the `pipeline-v3` namespace. See
[GitHub's cache documentation](https://docs.github.com/en/actions/reference/workflows-and-actions/dependency-caching).

## Implemented changes

| Issue | Change |
|---|---|
| Deployment retries repeated every source request | Separate build and deploy jobs; build/deploy timeouts of 45/15 minutes |
| Reruns created ambiguous Pages artifacts | Artifact names include run ID and attempt; deploy consumes the build job's exact output |
| Retry artifacts expired too quickly | Seven-day retention window |
| Pipeline edits did not trigger refresh | Push filters include Python, SQL, schemas, tests, and reference inputs |
| Validation history reset on every runner | Cache `_runs.jsonl` with source snapshots; save only validated builds |
| Failed or empty site responses removed available history | Merge fresh sites with the newest usable cached series per site; report fallback and served coverage |
| Partial source failures appeared fully healthy | Show population/source warnings and orange degraded-history bars |
| Population tests assumed a fixed row count | Check balanced region/year coverage with at least seven years |
| Flow card used a fixed percentile claim | Display the computed range and direct readers to observation dates |
| Historical labels could identify the wrong provider | Apply ORC-specific labels only to ORC observations |
| Regional loss estimates appeared measured | Add estimate labels and population-extrapolation assumptions |
| Build timestamps implied source freshness | Label build/processing times separately from NEPR and population years |
| Mobile cards clipped longer explanations | Allow card height to follow content |
| Smoke checks missed data-loading failures | Wait for data, inspect HTTP/console errors, check text clipping, and optionally save screenshots |
| Setup and refresh documentation was incomplete | Correct image links, installation steps, environment export, and manual reference-data maintenance |

Six offline regression cases cover partial failure, empty responses, all-site
failure with and without cache, successful recovery, and retrieval from older
snapshots. Deployment failure remains visible; it is not converted into a
successful workflow result.

## Analytical review

The regional scenario applies network per-capita supply to the entire regional
estimated resident population, then applies a population-weighted loss rate.
It includes people outside reporting networks and does not use supply-weighted
loss rates. These outputs must not be described as measured network totals.

| Basis | Daily supply, m³ | Daily loss, m³ |
|---|---:|---:|
| Sum reported annual values, divided by 365 | 1,178,309 | 264,779 |
| Current regional population extrapolation | 1,326,635 | 298,671 |

The site, README, and analysis now disclose the scenario basis. SQL values
were preserved. Evidence: [metric audit](incidents/2026-10-10/metric-audit.json).
Reported sums also depend on missingness and reporting coverage; they are not
independently verified complete regional totals.

Remaining priorities:

- Publish reported network supply, reported loss, and regional scenarios as
  separate measures. Compute aggregate loss rates from total loss/total supply.
- Align served-population efficiency scenarios with regional-population growth
  scenarios before interpreting the existing 62% comparison.
- Treat claims about the cheapest intervention or years of capacity headroom
  as hypotheses until costs, recoverable loss, and feasibility are assessed.
- Add explicit base/projection years; current column and chart labels assume
  2025 and 2030 even when the newest population year changes.
- Test and correct seasonal windows at December/January boundaries and leap
  days. Verify Hilltop date inclusivity and source time zones.
- Reduce repeated historical requests through incremental fetches and reuse
  of unchanged ORC data.
- Distinguish observation, fetch, source-release, and build dates; define
  source-specific freshness thresholds.
- Add public-source offline build fixtures. Some data-dependent tests skip
  on a clean clone until processed datasets exist.
- Keep water-quality/land-use analysis explicitly pending and review action
  runtime upgrades against official releases.

Validation-history bars describe validated builds, not deployment outcomes.
Cache eviction can reset history. Fetches that stop before validation and
failed deployments may not appear in the published history panel.

## Operational follow-up

For a Pages 502, first confirm the build passed. Within the artifact retention
window, rerun the failed deploy job to reuse the validated artifact. For a
fetch or validation failure, inspect source status, fallback coverage, schemas,
and tests rather than assuming the same deployment error.

```bash
make test
.venv/bin/python scripts/transform.py
.venv/bin/python scripts/validate.py
make site-data
.venv/bin/python scripts/smoke_mobile.py --screenshot /tmp/nz-dashboard-mobile.png
node --check site/app.js
git diff --check
```
